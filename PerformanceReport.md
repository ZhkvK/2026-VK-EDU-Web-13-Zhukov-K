# Отчет о результатах нагрузочного тестирования (ДЗ №7)

В ходе выполнения задания было проведено сравнение производительности веб-сервера **Nginx 1.30.2** и WSGI-сервера **Gunicorn** с использованием утилиты Apache Benchmark (`ab`).

## Сводная таблица результатов

| Сценарий тестирования | Requests per second (RPS) | Time per request (mean) |
|:---|:---:|:---:|
| 1. Статика через **Nginx** (`/sample.html`) | **54 588.13** | 1.832 ms |
| 2. Статика через **Gunicorn** (`/static/sample.html`) | **5 320.48** | 18.795 ms |
| 3. Динамика через **Gunicorn** (напрямую) | **147.73** | 676.891 ms |
| 4. Динамика через **Nginx** (проксирование) | **152.80** | 654.471 ms |
| 5. Динамика через **Nginx** (**proxy_cache**) | **18 496.60** | 5.406 ms |

---

## Анализ результатов и ответы на вопросы

### 1. Насколько быстрее отдается статика по сравнению с WSGI?

Согласно результатам тестов, отдача статического файла через **Nginx** происходит в **10.2 раза быстрее**, чем отдача того же файла через **Gunicorn** (54 588 RPS против 5 320 RPS).

Если же сравнивать отдачу статики через Nginx с генерацией динамического контента через WSGI (Django), разница становится колоссальной: Nginx отдает статику в **369 раз быстрее**, чем Gunicorn исполняет код приложения (54 588 RPS против 147 RPS).

**Вывод:** Nginx значительно эффективнее работает с файловой системой благодаря асинхронной архитектуре и отсутствию накладных расходов на интерпретацию Python-кода. Использование Gunicorn для раздачи статики в продакшн-среде крайне неэффективно.

### 2. Во сколько раз ускоряет работу proxy_cache?

Использование модуля `proxy_cache` в Nginx показало впечатляющие результаты. При кэшировании динамического ответа производительность выросла со 152.80 RPS до 18 496.60 RPS.

**Ускорение составило примерно 121 раз.**

**Вывод:** Технология `proxy_cache` позволяет Nginx отдавать результат предыдущего запроса напрямую из оперативной памяти или диска, полностью исключая из цепочки медленный бэкенд (Python/Gunicorn) и запросы к базе данных. Это позволяет серверу выдерживать нагрузки, в сто раз превышающие возможности самого приложения, при этом время отклика (Latency) снижается с 654 мс до 5 мс.
